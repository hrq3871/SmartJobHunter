## 岗位描述
{duty}

---

请判断这个岗位是否匹配求职意向。你的判断必须基于岗位职责和候选人意向之间的真实关系，不能把关键词命中当成匹配。

**判断原则：**
1. **核心职责优先**：先判断岗位实际做什么，再看标题。标题含关键词但职责不相关，应降分。
2. **关键词只是线索**：关键词只能作为辅助证据，不能单独决定保留。
3. **区分强匹配和弱相关**：
   - 强匹配：岗位核心职责与意向方向一致，例如 AI Agent 产品规划、大模型应用落地、ToB SaaS 产品。
   - 弱相关：只在工具、背景或部门名里出现关键词，但岗位实际是运营、销售、标注、审核等。
4. **识别反例**：如果岗位是“AI 标注运营”“数据审核”“供应商管理”等，即使命中 AI/数据关键词，也不能算 AI 产品岗位。
5. **保留不确定性**：信息不足时给出 concerns，不要编造岗位内容。

**评分维度：**
- core_role_fit: 是否符合目标岗位角色，例如产品经理/产品负责人/产品策划。
- domain_fit: 是否符合目标方向，例如大模型、Agent、ToB SaaS、企业服务。
- responsibility_fit: 岗位职责是否包含目标工作内容，例如需求分析、产品规划、落地推进。
- preference_fit: 地点、岗位性质、行业偏好是否一致。
- risk_signals: 是否存在岗位噪声，例如纯运营、标注、外包管理、销售、客服。

**输出格式 (JSON):**
```json
{
  "match_score": 0.8,
  "match_reason": "岗位是TOB SaaS产品方向，符合求职者的企业服务偏好",
  "match_reasons": [
    "核心职责包含产品规划和需求分析",
    "岗位方向明确涉及大模型应用落地"
  ],
  "should_keep": true,
  "concerns": ["地点在上海，求职者期望北京"],
  "evidence": {
    "core_role": ["产品规划"],
    "domain": ["大模型", "Agent"],
    "risk_signals": []
  }
}
```

**评分标准:**
- 0.8-1.0: 高度匹配
- 0.6-0.8: 基本匹配
- 0.4-0.6: 部分匹配
- 0.0-0.4: 不匹配

**保留阈值：**
- conservative: `match_score >= 0.8`
- moderate: `match_score >= 0.6`
- aggressive: `match_score >= 0.4`
